# 반쪽그림

두 사람이 그림을 반씩 이어 그리는 Next.js 앱입니다. 방장이 왼쪽 절반을 등록하고 참여 코드를 전달하면, 참여자가 오른쪽을 그려 완성합니다.

### 주제 추천·완성 공유 카드 — 2026-10-18

그리기 화면의 캔버스 위 ‘주제 추천’에서 32개 주제 중 3개를 추천합니다. ‘다른 주제 추천’은 현재 주제/입력 중인 주제/직전 추천과 겹치지 않는 후보를 제안합니다. 직접 다듬어 ‘이 주제로 그리기’를 누르면 기존 주제 입력란과 연결됩니다. 취소는 기존 주제를 바꾸지 않고, 추천이나 수정은 그림을 지우거나 방을 등록하지 않습니다. 선택한 주제는 기존 임시 저장으로 복원됩니다.

완성 화면에서는 ‘그림만’과 ‘공유 카드’를 선택합니다. 기본은 기존 원본 공유이고, 카드 선택 시 실제 완성 그림 전체와 주제·반쪽그림 이름·공개 사이트 주소를 담은 1200×1200 PNG를 이 브라우저에서 만듭니다. 카드 미리보기를 본 뒤 공유하거나 `half-drawing-card.png`로 저장할 수 있습니다. 기존 `half-drawing.png` 원본 저장(800×500)은 항상 별도로 제공합니다. 네이티브 파일 공유 미지원이면 선택한 형식으로 다운로드하고, 공유 취소는 다운로드하지 않습니다.

카드에는 참여 코드·방 주소를 넣지 않으며 외부 이미지 서비스나 공개 저장소에 업로드하지 않습니다. 사이트 주소는 `NEXT_PUBLIC_SITE_URL`의 호스트만 표시하고 미설정 시 `half-drawing-prac.vercel.app`을 사용합니다. DB 스키마·RPC 변경은 필요 없습니다. `npm run test:topics-card`로 추천/수정/취소/복원/등록, 카드 실제 픽셀·지우개 흰색·파일 크기·공유 취소/다운로드 대체·원본 보존·카드 준비 실패 후 재시도를 검사합니다. API와 네이티브 공유는 테스트 응답입니다.

### 색상 탭 보완 — 2026-10-18

기본색 6개와 파스텔색 6개, 최근 사용한 색 최대 5개, 현재 펜 색/굵기의 SVG 선 미리보기를 제공합니다. 최근 색은 실제 펜 선을 완료할 때만 기록하며, 다시 쓴 색을 앞으로 옮깁니다. 단순 색 선택·지우개는 사용 기록을 바꾸지 않습니다. 직접 고른 색도 포함하고 기존 도구 설정과 함께 이 브라우저에 저장합니다. 예전 설정에는 빈 최근 색 목록을 적용하고 잘못된 값은 무시합니다. 처음에는 ‘선으로 그린 색이 여기에 모여요.’ 안내를 표시합니다.

두 탭의 공통 창 높이는 최대 540px이며 좁거나 낮은 화면에서는 내용만 스크롤합니다. 기본색·최근 색을 눌러도 창은 유지되고 선 미리보기가 바로 갱신됩니다. 미리보기와 ‘이 색으로 그리기’ 버튼은 아래에 고정하며 이 버튼 또는 상단 닫기를 눌러 그림으로 돌아갑니다. 낮은 가로 화면에서는 미리보기와 버튼을 나란히 배치합니다. `npm run test:colors`로 320/390px 세로, 844×390 가로 및 데스크톱에서 12색/최근 색 선택 후 창 유지·미리보기 상시 노출·복귀·실제 사용 이력·중복/순서/개수 제한·새로고침 복원을 확인합니다.

### 헤더·그림 도구 통일 — 2026-10-17

홈·그리기·참여한 방·완성 화면의 로고와 메뉴는 같은 크기/여백을 사용합니다. 앞선 기록의 작업 화면 전용 축소 헤더를 공통 헤더로 대체했습니다. 도구 창은 왼쪽 ‘색상’, 오른쪽 ‘굵기 · 작업’ 순서이며 두 버튼의 크기는 같습니다. 창 높이는 최대 540px로 고정하고 작은 화면에서는 내용만 스크롤하므로 탭/펜/지우개 전환에 따라 창이 커지거나 작아지지 않습니다.

굵기 화면에는 선택한 도구의 슬라이더 하나만 표시합니다. 바깥 도구 막대나 굵기 화면에서 펜/지우개를 선택하며, 각 도구의 독립적인 굵기는 계속 기억합니다. `npm run test:tools`는 320×740/390×844/1440×1000/844×390에서 화면 간 메뉴·로고 크기, 탭 순서/크기, 창/캔버스 위치 유지, 선택 도구의 굵기만 표시와 설정 보존을 확인합니다. API는 테스트 응답을 사용합니다.

## 실행

Node.js 및 npm을 설치한 뒤 프로젝트 루트에서 실행합니다.

```bash
npm ci
npm run dev
```

Windows PowerShell에서 npm 실행 정책 오류가 나면 `npm.cmd ci`, `npm.cmd run dev`를 사용하세요. 로컬 주소는 `http://localhost:3000`입니다.

`.env.example`을 참고해 `.env.local`을 만들고 Supabase 프로젝트의 URL과 publishable key를 넣으세요. `service_role` 키를 `NEXT_PUBLIC_` 변수에 넣으면 안 됩니다. Supabase에서 익명 로그인을 켜고 `rooms`, `drawings`, `create_room`, `join_room`, `complete_room_if_ready` 및 해당 RLS 정책을 준비해야 합니다. 기존 DB 구조는 이 저장소에서 생성하지 않으므로 배포 대상 Supabase 프로젝트에 이전 SQL 설정이 적용되었는지 확인해야 합니다.

**필수 DB 변경:** 기존 Supabase 프로젝트의 SQL 편집기에서 `supabase/migrations/20260928_guest_preview.sql`을 실행하세요. 이 스크립트는 참여자의 왼쪽 원본 읽기를 차단하고 경계 24px 안에 실제로 기록된 점만 반환하는 `get_left_preview` RPC를 만듭니다. 앱 코드 배포보다 SQL 적용을 먼저 해야 새 참여자 화면이 열립니다. 다른 허용형 `drawings` SELECT 정책이 추가되어 있으면 그것도 점검해야 합니다.

```bash
npm run lint
npm test
npm run build
```

## 화면 및 데이터 흐름

**내 보관함**(`/library`)에서 시작한 방과 참여한 방을 함께 다시 찾을 수 있습니다. 전체·시작한 그림·참여한 그림으로 필터링하며 최신순 6개씩 보여줍니다. 홈(`/`)은 그림 수와 관계없이 항상 예시 그림판과 ‘그림 시작하기’를 표시합니다. 보관함은 참여 대기·친구 참여(참여자에게는 이어 그릴 차례)·완성됨·기간 만료를 표시하고 완성 그림 보기와 방장용 참여 코드 복사를 제공합니다. 보이는 탭에서 10초마다 또는 탭으로 돌아올 때 갱신합니다. 친구 참여는 방에 들어왔다는 뜻이며 실제 펜 움직임은 감지하지 않습니다.

필터 버튼은 모눈종이 배경 위에 각각 표시합니다. 필터 전환과 자동 갱신은 새로고침 버튼을 바꾸지 않으며, 보관함 진입 시 세 필터의 첫 페이지를 병렬로 미리 불러옵니다. 준비된 필터/페이지는 메모리의 마지막 목록을 먼저 보여주고 서버에서 다시 확인합니다. 미리 불러오는 중인 필터를 눌러도 같은 요청을 재사용합니다. 수동 ‘상태 새로고침’을 눌렀을 때만 버튼에 진행 상태가 표시됩니다.

`getMyRooms`는 기존 세션의 사용자 ID와 `rooms.host_id` 또는 `rooms.guest_id`가 일치하는 방의 메타데이터만 조회합니다. 보관함 방문만으로 새 익명 계정을 생성하지 않습니다. 홈은 목록 조회 자체를 실행하지 않습니다. 기존 rooms SELECT RLS를 그대로 사용합니다. 운영 DB에서 방장과 해당 참여자의 방 읽기가 허용되어 있어야 하며 이번 작업에서 원격 SQL은 변경하지 않았습니다. 브라우저 데이터를 지우거나 다른 기기를 사용하면 익명 계정이 달라져 이전 목록을 찾을 수 없습니다. 이 제약은 목록 위에 펼쳐진 안내로 표시합니다. 조회 실패는 빈 목록으로 숨기지 않고 재시도 안내를 표시합니다.

완성된 카드가 화면에서 120px 이내에 들어오면 해당 방의 완성 그림을 별도로 읽어 320×200 썸네일을 만듭니다. 쿼리에도 `status=completed` 조건을 적용하고 양쪽의 완료 상태·선 형식을 검사합니다. 미완성 방에는 썸네일 요청이 없고, 세 필터의 사전 조회는 메타데이터만 읽습니다. 다른 페이지의 원본을 미리 받지 않습니다. 각 썸네일은 최초 표시 시 선 데이터 다운로드가 필요하며, 서버에서 이미 축소된 이미지를 받는 방식은 아닙니다. 만든 이미지는 해당 보관함 방문의 메모리에 최대 24개까지 보관하고 요청을 재사용하며 공개 저장소나 localStorage에는 저장하지 않습니다. 미리보기 오류는 카드 열기·필터·목록 조회를 막지 않습니다.

그림을 등록하거나 제출한 뒤에는 캔버스와 편집 도구가 잠겨, 화면과 저장된 데이터가 다르게 보이지 않도록 합니다. 생성 직후와 방장 대기 화면에서 참여 코드를 복사할 수 있습니다. 방장 화면은 탭이 보이는 동안 약 7초마다 완료 여부를 확인합니다. 휴대폰에서도 전체 캔버스를 화면 폭에 맞춰 표시하며 중앙선을 항상 볼 수 있습니다. 그리기와 대기 미리보기는 같은 크기 규칙을 사용합니다. 저장 좌표는 기기 크기와 관계없이 800×500 기준이며 중앙은 x=400입니다.

완료한 선은 브라우저의 `localStorage`에 임시 저장됩니다. 같은 브라우저에서 새로고침하면 복원되며, 오른쪽 그림은 방 ID별로 구분됩니다. 서버와 동기화되는 저장은 아니므로 다른 기기나 시크릿 창에서는 이어서 그릴 수 없습니다. 방 생성 또는 그림 제출에 성공하면 해당 임시 그림은 삭제됩니다. 그리는 중인 선은 포인터를 놓아 완료하기 전까지 임시 저장되지 않습니다.

방장이 주제를 입력하다 새로고침해도 같은 브라우저에서 입력값을 복원합니다. 방을 생성하면 대기 화면으로 이동하므로 참여 코드를 다시 확인할 수 있습니다. 대기 화면에는 등록한 왼쪽 그림이 표시되고, 전체 지우기 전에는 되돌릴 수 없다는 확인을 받습니다.

| 경로 | 역할 |
| --- | --- |
| `/` | 항상 표시하는 예시 그림판과 그림 시작/방 참여 안내 |
| `/library` | 내가 시작하거나 참여한 방 목록과 완성 상태 확인 |
| `/draw` | 방장이 왼쪽 그림을 그려 주제와 함께 등록 |
| `/join` | 다른 익명 계정으로 참여 코드 입력 |
| `/rooms/[id]` | 방장은 완성 여부를 확인하고, 참여자는 오른쪽을 그리며, 완료되면 양쪽 완성 그림을 표시 |

`useDrawingHistory`는 현재 그림과 취소한 그림을 관리합니다. `useCanvasDrawing`은 포인터 입력을 캔버스 좌표로 바꾸고 선을 그립니다. `drawStroke`는 저장된 선을 다시 재생하므로 실행 취소, 지우개, 결과 화면에서 같은 그림을 얻을 수 있습니다. `create_room` RPC는 방과 첫 번째 그림을 생성하고, 오른쪽 제출은 `drawings`에 저장됩니다. DB 트리거가 방을 `completed`로 바꾸면 `/rooms/[id]`에서 완성본을 확인합니다.

## 출시 전 실제 환경 확인

이번 UI/UX 개선 내역과 출시 승인 전 점검표는 `RELEASE_CHECKLIST.md`, 버그 수정·보안 업데이트·25개 테스트 결과와 출시 판정은 `QA_REPORT.md`에 정리했습니다. 자동 검사는 실제 Supabase 두 계정 테스트나 실제 휴대폰 브라우저 테스트를 대신하지 않습니다.

1. 일반 브라우저와 별도 시크릿 창에서 각각 익명 로그인으로 방장/참여자를 만듭니다.
2. 방장이 그림을 등록하고 코드를 복사한 뒤 방 화면에서 대기합니다.
3. 참여자가 코드로 들어와 오른쪽을 그리고 제출합니다. 새로고침해도 다시 편집되지 않고 완성본이 보이는지 확인합니다.
4. 방장 화면에서 `완성 여부 확인`을 누르고 두 그림이 공개되는지 확인합니다.
5. 참여자 계정으로 `drawings` 테이블의 왼쪽 원본을 직접 SELECT해도 나오지 않는지 확인하고, `get_left_preview` 결과의 모든 점이 x=376..400인지 확인합니다.
6. 실패한 코드, 만료된 방, 중복 제출, 모바일 터치, 펜/지우개, PNG 저장을 점검합니다.

### 현재 공개 출시 전 제약

빗살무늬만으로는 그림이 비밀이 되지 않습니다. 위 SQL을 적용하면 완료 전 참여자의 원본 SELECT가 거부되고 경계 근처의 점만 별도 RPC로 전송됩니다. 프리뷰는 선의 점 중 x=376..400에 기록된 점만 남기므로 원래의 선과 약간 다르게 보일 수 있습니다. SQL 적용과 실제 RLS 검증 없이 UI만 배포하면 참여자가 개발자 도구로 원본 그림을 볼 수 있습니다.

현재 저장소에는 Supabase 프로젝트의 접속 정보와 배포 플랫폼 설정이 없습니다. 배포할 때 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY`를 설정하고 익명 로그인과 RPC 권한을 실제 배포 주소에서 다시 확인하세요.

## 모바일 도구와 공유

기본 도구는 동일한 크기의 펜·지우개, 실행 취소 아이콘, 색상입니다. 실행 취소·다시 실행 아이콘에는 접근성 이름과 설명을 제공합니다. ‘굵기 · 더 많은 도구’를 펼치면 굵기 미리보기, 빠른 색상, 다시 실행, 전체 지우기와 PNG 저장을 사용할 수 있습니다. 모바일과 데스크톱 모두 새 그림·참여한 방은 일반 작업 화면으로 시작합니다. ‘내 반쪽 크게 그리기’를 누르면 그리는 쪽만 화면에 맞춰 더 크게 표시됩니다. 방장은 왼쪽 절반을, 참여자는 오른쪽 절반과 얇은 경계 힌트를 봅니다. 좌우 이동은 필요 없으며 전체 보기는 돌아가기 버튼으로 확인합니다. 돌아가기 버튼 또는 Escape로 일반 화면으로 복귀합니다. 저장 좌표는 그대로 800×500입니다. 등록·완료 직전에 수정 불가 확인을 받습니다.

방장 대기 화면의 ‘친구에게 초대 링크 공유’는 지원 브라우저에서 공유창을 열고, 그 외에는 링크를 복사합니다. 링크에는 참여 코드가 포함되므로 참여할 친구에게만 보내세요. 링크를 연 참여자는 코드가 미리 입력된 상태에서 직접 참여 버튼을 누릅니다. 완성 그림은 이미지 공유가 가능하며, 파일 공유 미지원 브라우저에서는 PNG 다운로드를 요청합니다. 공유 취소는 실패나 성공으로 표시하지 않습니다.

## 방해를 줄인 수동 광고

AdSense 수동 배너 연결을 준비했습니다. 설정이 없거나 `NEXT_PUBLIC_ADSENSE_ENABLED`가 `true`가 아니면 광고 칸·여백·외부 스크립트가 모두 생기지 않습니다. 현재 광고 계정과 슬롯이 없어 실제 광고는 꺼져 있습니다.

- 완성 화면의 공유·PNG 저장·다음 행동 버튼 뒤와, 데이터가 있는 보관함의 목록·페이지 이동 아래에만 페이지당 배너 한 개를 둡니다. 홈·새 그림·이어 그리기·참여·친구 대기·빈 목록·목록 오류에는 광고를 넣지 않습니다.
- 버튼에서 40px 떨어진 곳에 ‘광고’를 표시하고 높이 100px를 미리 확보합니다. 광고 가까이(160px)에 스크롤했을 때만 스크립트를 불러옵니다. 고정·팝업·전면·동영상 광고와 자동 새로고침은 구현하지 않습니다.
- 광고 미충족·스크립트 실패·20초 동안 응답 없음은 광고 영역을 접습니다. 공유 형식 변경·보관함 새로고침·데이터가 있는 필터 간 전환은 기존 광고를 다시 요청하지 않습니다. SPA 페이지 이동 시 스크립트는 재사용합니다.

연결 순서:

1. AdSense에 가입하고 실제 배포 도메인을 사이트로 추가합니다. 게시자 ID(`ca-pub-` 뒤 16자리)를 Vercel의 `NEXT_PUBLIC_ADSENSE_CLIENT`로 설정하고 재배포하면 사이트 확인용 `google-adsense-account` 메타 태그와 `/ads.txt`가 만들어집니다. 광고 활성화 전에도 이 확인 정보는 제공됩니다.
2. 디스플레이 광고 단위를 두 개 만들고 10자리 슬롯 ID를 `NEXT_PUBLIC_ADSENSE_COMPLETED_SLOT`, `NEXT_PUBLIC_ADSENSE_LIBRARY_SLOT`에 넣습니다. 슬롯 하나만 설정하면 해당 위치만 사용합니다.
3. **AdSense의 자동 광고(Auto ads)는 끄세요.** 이 구현은 수동 배너만 배치합니다. 자동 광고를 켜면 Google이 고정·전면 광고 등 다른 위치를 추가할 수 있어 코드의 배치 의도와 달라집니다.
4. `NEXT_PUBLIC_ADSENSE_ENABLED=true`, `NEXT_PUBLIC_ADSENSE_TEST_MODE=true`로 재배포해 테스트 광고부터 확인합니다. 테스트 모드는 기본 켜짐입니다. 사이트 승인과 개인정보처리방침·해당 지역에 필요한 동의 설정 등 AdSense의 실제 운영 요건을 완료한 뒤 `NEXT_PUBLIC_ADSENSE_TEST_MODE=false`로 재배포해야 실제 광고 요청이 됩니다. 코드 연결이 사이트 승인이나 광고 공급·수익을 보장하지는 않습니다.
5. 끌 때는 `NEXT_PUBLIC_ADSENSE_ENABLED=false`로 재배포합니다. `NEXT_PUBLIC_` 설정은 빌드에 반영되므로 값 변경 후 재배포가 필요합니다. 게시자/슬롯 ID는 공개 식별자이며 비밀 키가 아닙니다.

`npm run test:ads`는 기본 비활성 상태를 검사합니다. 테스트용 ID로 활성화한 빌드에서는 `TEST_ADS_ENABLED=true npm run test:ads`로 320/390/1440px의 배치·지연 로딩·스크립트 재사용·실패/미충족/시간 초과·작업 화면 제외를 검사합니다. 광고 스크립트는 로컬 테스트 응답으로 대체하며 실제 광고를 요청하거나 클릭하지 않습니다. 모바일 카카오톡/Safari와 실제 AdSense 광고 크기·공급은 계정 연결 후 별도로 확인해야 합니다.
